# マニュアル検索

大量のPDFマニュアルを、**機種を選んで中身から検索**できるようにするシステムです。
スキャンしただけのPDFはOCRにかけ、章立てやエラーコードまで抜き出して索引にします。
ChatGPTのAPIキーを入れると、自然文で相談することもできます。

検索エンジンのサーバーは不要です。SQLite（FTS5）のDBファイル1つで動きます。

```
PDF ──▶ テキスト抽出 / OCR ──▶ 1冊ずつ分析 ──▶ SQLite(FTS5) ──▶ 検索画面
        (PyMuPDF/Tesseract)   章立て・コード      DBファイル1つ    └ AIに相談
                              ・機種の推定                          (任意)
```

## すぐ試す

**macOS / Linux**

```bash
./start.sh
```

**Windows**

`start.bat` をダブルクリック。

事前に [Python](https://www.python.org/downloads/) が必要です。インストール時に
**「Add python.exe to PATH」にチェック**を入れてください（入っていないと `start.bat` が
Pythonを見つけられません）。入っていなければ `start.bat` がその旨を表示して止まります。

初回だけ仮想環境の作成と依存関係のインストールが走ります（1〜2分）。
そのあと索引を作り、ブラウザで検索画面が開きます。2回目以降は増えたPDFだけ読み直すので、
起動は数秒です。

PDFが1つも無いときはサンプルを作るか聞かれるので、`y` で動作を確認できます。

### 手元のコピーが最新か確かめる

画面の右下と「設定」タブに **バージョン** が出ます。タブが
`キーワード検索 / AIに相談 / マニュアル一覧 / 設定` の4つ揃っていれば最新です。
タブが2つしか無い場合は古いコピーなので、ダウンロードし直してください。

古いフォルダの `manuals` に入れたPDFは、新しいフォルダの `manuals` へ移せば
そのまま使えます（索引は `start.bat` が作り直します）。

### うまく動かないとき（Windows）

**原因が分からないときは `診断.bat` をダブルクリック**してください。環境を調べて
`診断結果.txt` を作り、メモ帳で開きます。Pythonの有無、必要なファイルが揃っているか、
仮想環境が壊れていないか、索引作成のエラーまで記録されます。

**「管理者として実行」しないと動かない場合**、そのフォルダに書き込む権限がありません。
このアプリは自分のフォルダに仮想環境・索引・台帳を作るので、書き込めないと動きません。
毎回管理者で実行するのは避けて、次のどちらかで直してください。

- フォルダを右クリック → プロパティ → セキュリティ → 編集 で、お使いのユーザーに
  **「変更」を許可**する（一度だけ）
- `C:\manual-serch` やドキュメントの下など、**書き込める場所へ移す**

管理者で作ったファイルは管理者のものになるため、あとから普通に起動すると
また失敗します。

**黒い画面が一瞬で閉じてしまう場合**、エラーメッセージを読むために手動で実行します。

1. エクスプローラーでこのフォルダを開く
2. アドレスバーに `cmd` と入力して Enter（黒い画面がこのフォルダで開きます）
3. `start.bat` と入力して Enter

ウィンドウが残るので、何が足りないか表示されます。よくある原因は Python の未導入、
または PATH への未登録です。

> `start.bat` は **UTF-8 + CRLF** で保存する必要があります。改行がLFだけになっていると、
> `cmd.exe` がラベルや `if` の解析に失敗し、何も表示せずウィンドウが閉じます。
> リポジトリでは `.gitattributes` で改行を保護しています（`*.bat -text`）ので、
> エディタで編集するときは改行コードを変えないでください。

## PDFの置きかた

**`manuals` フォルダは最初から用意してあります。** その中に、**機種ごとのフォルダ**を
作ってPDFを入れてください。フォルダ名が「使っている機械」の選択肢になります。
末尾の「マニュアル」「取扱説明書」などは自動で落とすので、
`ロボドリルマニュアル` というフォルダは `ロボドリル` と表示されます。
（置き方の説明が `manuals\はじめにお読みください.txt` にも入っています）

```
manuals/
├── ロボドリル/
│   ├── α-D21MiB5_操作説明書.pdf
│   └── α-D21MiB5_保守説明書.pdf
├── ワイヤーカット/
│   └── ...
└── library.csv        ← 一覧の台帳（任意）
```

## 使いかた

### 画面

| 画面 | できること |
|---|---|
| キーワード検索 | 機種を選んで型番・エラーコード・部品名で引く。ヒットしたページのPDFがその場で開く |
| AIに相談 | 「ロボドリルでSV0417が出た」のように書くと、根拠ページ付きで答える（APIキーが必要） |
| マニュアル一覧 | 登録済みマニュアルの一覧。**機種と分類をこの画面で直接編集できる** |
| 設定 | APIキーの登録、OCRの状態、置き場所の確認。**保存すると再起動なしで反映される** |

選んだ機械はブラウザが覚えるので、毎回選び直す必要はありません。

### 検索の書きかた

| 入力 | 意味 |
|---|---|
| `エラー 点滅` | 両方を含むページ（AND） |
| `"冷却 ファン"` | 空白を含めてこの並びどおり |
| `ポンプ -旧型` | 「旧型」を含むページを除く |

全角・半角は自動でそろえるので、`Ｅ２０３` でも `E203` でも同じ結果になります。
日本語の空白や改行で割れた語（`マ ニ ュ ア ル`、行末で切れた `エラーコ`＋`ード`）も
取り込み時に直しているので、そのまま引けます。

> **3文字以上で引いてください。** 索引に使っている FTS5 の trigram トークナイザは
> 2文字以下の語を扱えません。1〜2文字だけの検索は全ページ走査になり、遅くなります。

### ニュアンスで探せるか

**「検索」タブは字面が一致したページしか返しません。** これはローカルAIでも
OpenAIでも変わりません。検索そのものはPCの中のデータベース（SQLite FTS5）が
やっていて、AIは一切関わっていないからです。「異音」で引いたページに
「変な音」とだけ書いてあれば当たりません。

**「AIに相談」タブは、そこを埋めるためにあります。** 質問文をそのまま検索するのでは
なく、AIがまず「マニュアルに載っていそうな言葉」へ翻訳してから検索します。

```
「ロボドリルから変な音がする」
        ↓ AIが検索語に翻訳
   異音 / 異常音 / 振動 / 主軸
        ↓ ここから先は普通の全文検索
   当たったページの本文だけをAIに渡して答えさせる
```

つまり**ニュアンスは通じます**が、通じ方はAIの語彙しだいです。話し言葉を業界の
書き言葉に置き換えられるかどうかで決まるので、

- 32B級（`qwen3:32b` など）… 日本語の技術用語の言い換えはおおむね出せます
- 7〜8B級 … 質問文の単語をほぼそのまま検索語にしがちで、外しやすい

という差が出ます。**ローカルだから当たらない、のではなく、モデルが小さいと
当たりにくい**、が正確なところです。

最初の検索語が全部外れたときは、語を分解したり質問文から直接切り出したりして
もう一度だけ検索し直します。それでも駄目なときは、正式名称や型番、エラーコードを
1つ混ぜて聞き直すと確実です（例:「変な音」→「主軸の異音」「SP1241」）。

## コマンド

`start.sh` / `start.bat` の代わりに、細かく操作したいとき。

```bash
python -m manualsearch <コマンド>
```

| コマンド | 用途 |
|---|---|
| `index <PDF置き場>` | フォルダごと取り込む。2回目以降は増減したPDFだけ処理する |
| `add <PDF> --machine ロボドリル` | **1冊だけ**取り込んで、分析結果を表示する |
| `analyze <PDF>` | 取り込まずに、章立て・コード・機種候補の下見だけする |
| `set <パス> --machine ...` | 取り込み済みマニュアルの機種・分類・名前を後から直す |
| `library [--init]` | 一覧の台帳を見る／PDFから下書きを作る |
| `search <語>` | 端末から検索する（`--machine` で機種を絞る） |
| `code E203` | エラーコードから該当ページを直接引く |
| `ask <質問>` | ChatGPTに相談する |
| `serve <PDF置き場>` | 検索画面を起動する |
| `stats` / `optimize` / `doctor` | 索引の状況確認・最適化・動作環境の確認 |

1冊ずつ確認しながら育てていく流れはこうなります。

```bash
python -m manualsearch analyze 新しいマニュアル.pdf          # まず中身を見る
python -m manualsearch add manuals/ロボドリル/新しいマニュアル.pdf \
       --machine ロボドリル --category 保守                  # 納得したら登録
python -m manualsearch set ロボドリル/新しいマニュアル.pdf \
       --title "α-D21 保守説明書 2024年版"                    # あとから直す
```

## 1冊ごとの分析でやっていること

取り込み時に、PDF1冊ずつ次を調べて索引に入れます。

- **章立て** — PDFのしおりを読む。しおりが無ければ `第3章 …` `3.2 …` `■ …` のような
  見出し行を本文から拾う。検索結果に「どの章の話か」が出ます。
- **ページと章の対応** — どのページがどの章に属するかを決めます。
- **エラーコード・アラーム番号** — 「エラーコード E203」のように前置きが付いた形を拾い、
  同じページに並ぶ一覧表のコードもまとめて拾います。`code` コマンドで直接引けます。
- **型番・機種の候補** — フォルダ名 → ファイル名の型番 → 表紙の型番、の順に推定します。
- **本文が取れているか** — 取れないページが多ければOCRを促します。

推定結果はすべて `library.csv` で上書きできます（下記）。

## マニュアル一覧（library.csv）

`manuals/library.csv` を置くと、ファイル名だけでは分からない情報を足せます。無くても
動きます。**Excelで開いて編集できます**（BOM付きUTF-8で読み書きします）。

```csv
path,machine,title,category,tags,note
ロボドリル/α-D21MiB5_操作説明書.pdf,ロボドリル,α-D21MiB5 操作説明書,操作,段取り アラーム,2024年改訂
```

| 列 | 意味 |
|---|---|
| `path` | PDF置き場からの相対パス（これだけ必須） |
| `machine` | 機種名。「使っている機械」の選択肢になる。空ならフォルダ名を使う |
| `title` | 画面に出す名前。空ならPDFのタイトル、それも無ければファイル名 |
| `category` / `tags` / `note` | 分類・タグ・メモ |

下書きは自動で作れます。

```bash
python -m manualsearch library manuals --init   # 見つかったPDFを全部並べたCSVを書き出す
# Excelで machine / title / category を埋める
python -m manualsearch index manuals            # 反映（PDFは読み直さないので一瞬）
```

## スキャンしたPDF（OCR）

テキストを持たないページだけを自動で見つけてOCRにかけます（`--ocr auto`、既定）。
テキストPDFとスキャンPDFが混ざった1冊でも、必要なページだけ処理します。

Tesseractの導入が必要です。

```bash
# Ubuntu / Debian
sudo apt install tesseract-ocr tesseract-ocr-jpn

# macOS
brew install tesseract tesseract-lang

# Windows
# https://github.com/UB-Mannheim/tesseract/wiki からインストール（言語で Japanese を選ぶ）
```

導入できているかは `python -m manualsearch doctor` で確認できます。

| 指定 | 動き |
|---|---|
| `--ocr auto` | 本文が取れないページだけOCR（既定） |
| `--ocr never` | OCRしない。テキストPDFだけを速く取り込みたいとき |
| `--ocr force` | 全ページOCR。文字が画像で埋め込まれている図面などに |

縦書きが多い場合は `--lang jpn+jpn_vert+eng` を付けてください。

## ChatGPT連携（任意）

**画面上部の「設定」タブから登録するのが一番簡単です。** OpenAIのAPIキーを貼り付けて
保存すると、再起動なしですぐ「AIに相談」が使えます。キーは起動フォルダの `.env` に
保存されるので、次回以降も有効です。

ファイルで用意しておくこともできます。`.env.example` を `.env` という名前でコピーし、
`OPENAI_API_KEY=` の右にキーを書いてから起動してください。環境変数でも構いません
（環境変数のほうが `.env` より優先されます）。

```bash
export OPENAI_API_KEY=sk-...
./start.sh
```

答えかたは次のようにしています。

1. 質問文から検索語を作る（APIが落ちていても簡易抽出で検索まではたどり着きます）
2. その語で全文検索し、根拠になりそうなページを最大8ページ集める
3. **集めたページの本文だけ**を渡して答えさせる

マニュアル全体は送りません。根拠が無ければ「記載が見つかりません」と答えるよう指示して
あり、答えの中の `[1]` をクリックすると該当ページのPDFが開きます。作業前には必ず根拠
ページを確認してください。

**OpenAI と ローカルは、どちらも登録しておけます。** 設定画面で使う側を選ぶだけで
切り替わり、選ばなかった側の設定も残ります。いま何に繋がっているかは
**画面右上のバッジ**に常に出ています（例: `● ローカル qwen3:32b`）。
どこの何が答えたかは、「AIに相談」の回答のすぐ下にも書かれます。

| 環境変数 | 既定 | 用途 |
|---|---|---|
| `MANUAL_AI_PROVIDER` | `openai` | `openai` か `local`。どちらを使うか |
| `OPENAI_API_KEY` | （未設定） | OpenAIのAPIキー |
| `MANUAL_AI_MODEL` | `gpt-4o-mini` | OpenAIで使うモデル |
| `OPENAI_BASE_URL` | （未設定） | ローカルサーバーの接続先 |
| `MANUAL_LOCAL_MODEL` | （未設定） | ローカルで使うモデル |

## ローカルのAIで動かす（社外にデータを出さない）

OpenAI互換のAPIを持つローカルサーバーなら、そのまま繋がります。マニュアルの内容は
一切社外に出ません。設定画面の「**ローカルのAIサーバーを使う**」にチェックを入れて
保存するだけで切り替わります（APIキーは不要）。

[Ollama](https://ollama.com/) を使う場合の手順です。

```bash
ollama pull qwen2.5:14b-instruct   # モデルを取得（14Bで約9GB）
ollama serve                        # 既定で http://localhost:11434 で待ち受ける
```

設定画面で次のように入れて保存します。

| 項目 | 値 |
|---|---|
| ローカルのAIサーバーを使う | チェックを入れる |
| 接続先 | `http://localhost:11434/v1`（空欄ならこれが入ります） |
| モデル | `qwen2.5:14b-instruct` など、`ollama list` に出る名前 |
| APIキー | 空欄でよい |

LM Studio、llama.cpp の `llama-server`、vLLM など、OpenAI互換のエンドポイントを
出せるものなら同じ手順で使えます。JSONモード（`response_format`）に対応していない
サーバーでも動くようにしてあります。

### まず必ず: コンテキスト長を広げる

**ローカル運用でいちばん多い失敗がこれです。** この用途はマニュアル8ページ分
（約8千〜1万トークン）を読ませるので、コンテキスト長が足りないと**溢れた先頭が
黙って捨てられます**。エラーは出ません。気づかないまま「マニュアルを読んでいない
それらしい回答」が返り続けます。

**既定値はバージョンによって違います。** `4k` のこともあれば `32k` のこともあるので、
**まず接続テストで足りているか確かめてください。** 足りていれば何も触る必要はありません。

- `4k` … 足りません。マニュアルの大半が捨てられます
- `16k` … 必要十分
- `32k` … 余裕あり。**このままで構いません**
- `64k` 以上 … KVキャッシュでVRAMを食い、モデルが載り切らずCPUに溢れると激遅になります

不足していた場合、広げる方法は3つあります。**確実なのは C です。**

#### A. アプリの設定画面（動くならこれが一番早い）

タスクトレイの Ollama アイコン → **Settings** → **Context length** のスライダーを `16k` へ。
保存ボタンはありません。

つまみが見えず動かせないことがあります。その場合は目盛りの `16k` の位置を直接クリックするか、
一度クリックしてから矢印キー（←→）を試してください。それでも駄目なら B か C へ。

#### B. 環境変数

```bash
# Windows（PowerShell、恒久設定）
setx OLLAMA_CONTEXT_LENGTH 16384
setx OLLAMA_FLASH_ATTENTION 1
# 設定後、Ollama を終了して起動し直す
```

アプリ版は自分の設定を優先することがあり、これが効かない場合があります。

#### C. コンテキスト長を焼き込んだモデルを作る（確実）

元のモデルに設定を埋め込んだ**別名のモデル**を作ります。アプリ側の設定に
左右されないので、これが最も確実です。同梱のスクリプトをダブルクリックしてください。

```
scripts\make_ollama_model.bat
```

元にするモデル名（既定 `qwen3:32b`）とコンテキスト長（既定 `16384`）を聞かれるので、
そのままEnterで構いません。`qwen3-32b-ctx16384` という名前のモデルが作られるので、
それを設定画面の「モデル」欄に入れます。

手で行う場合は、次の内容で `Modelfile` を作り、

```
FROM qwen3:32b
PARAMETER num_ctx 16384
```

こう実行します。

```bash
ollama create qwen3-32b-ctx16k -f Modelfile
```

### Ollama 設定画面の他の項目

| 項目 | 推奨 | 理由 |
|---|---|---|
| **Cloud** | **オフ** | オンだとクラウド上のモデルも選べてしまいます。**社外にデータを出さないためにローカルにしているなら、切っておくのが安全**です |
| Expose Ollama to the network | オフのまま | このアプリは同じPC内から繋ぐので、外部に開ける必要はありません |
| Model location | 既定のまま | 変えるならCドライブの空きに注意（1モデル20GB前後） |

設定できているかは、**設定画面の「接続テスト」ボタン**で確かめられます。
長い文章の先頭に合言葉を仕込んで送り、それを答えられるかで切り捨てを検出します。

| 表示 | 意味 |
|---|---|
| 長い文章の読み取り **OK** | そのまま使えます |
| 長い文章の読み取り **NG** | 先頭が捨てられています。上の設定をしてください |

### 必要なPCの性能

この用途は「マニュアル8ページ分（**8千〜1万トークン**）を読ませて日本語で答えさせる」
という、入力が長い処理です。生成の速さより**長い入力を読む速さ**が効くので、
**GPUがほぼ必須**だと考えてください。

| 構成 | 動かせるモデル | 1問あたりの目安 | 実用性 |
|---|---|---|---|
| GPUなし（事務PC / 16GB RAM） | 7〜8B | 2〜5分 | 試すだけなら。日常利用は厳しい |
| RTX 4060 Ti 16GB / 4070 12GB | 14B | 15〜30秒 | **実用ライン** |
| RTX 4090 24GB / 5090 32GB | 32B | 10〜20秒 | クラウドに近い品質 |
| Mac (M3/M4 Pro・Max, 36GB以上) | 14〜32B | 20〜40秒 | メモリ帯域が効くので健闘する |

メモリの目安（4bit量子化）です。これに加えて入力を保持する領域が1〜2GB要ります。

| モデルの大きさ | 必要なVRAM |
|---|---|
| 7〜8B | 約5〜6GB |
| 14B | 約9〜10GB |
| 32B | 約20GB |

**回答の品質は正直に言うと落ちます。** 特に7〜8Bだと「マニュアルに書いていないことは
答えない」「出典番号を正しく付ける」といった指示を守りきれず、それらしい嘘が混じる
ことがあります。14B以上を推奨します。なお**検索そのものは全文検索なので、AIの
大きさに関係なく同じ精度**です。落ちるのは文章にまとめる部分だけです。

遅い場合は、根拠として渡すページ数を減らすと入力が短くなり速くなります。

```bash
python -m manualsearch ask "SV0417が出た" --sources 4   # 既定は8
```

### モデルの入れかた（Hugging Face から落とさないこと）

Hugging Face の `Qwen/Qwen3-32B` のようなページには **65.5GB** の
`safetensors` が並んでいますが、**これを落とす必要はありません**。あれは量子化前の
生の重みで、32GBのVRAMには載りませんし、Ollama はその形式を直接読めません。

**`ollama pull` を使ってください。** 量子化済みのものを自動で取ってきます。

```bash
ollama pull qwen3:32b       # 約20GB（4bit量子化済み）
ollama pull qwen3:30b-a3b   # 約19GB
ollama list                 # 入ったモデル名の一覧
```

`ollama list` に出た名前を、設定画面の「モデル」欄にそのまま入れます。
**設定画面の「接続テスト」を押すと、サーバーに入っているモデル名の一覧が表示される**ので、
名前を打ち間違えていればその場で分かります。

### ダウンロードしたあとの動き

モデルの実体は Ollama が自分の置き場（Windowsでは `C:\Users\<ユーザー名>\.ollama`）で
管理します。このアプリのフォルダには何も置きません。

1. Windows版の Ollama はインストール時に**常駐サービスとして登録**されるので、
   `ollama serve` を毎回叩く必要はありません（タスクトレイに常駐します）
2. 最初の質問が来たとき、モデルが**VRAMに読み込まれます**（20GBで10〜30秒）
3. 2問目以降は読み込み済みなので速く返ります
4. **5分間使わないとVRAMから降ろされます**。次の質問はまた読み込みからになります

つまり「**1問目だけ遅い**」という挙動になります。常時すぐ返したい場合は、
待機時間を延ばしてください。

```bash
setx OLLAMA_KEEP_ALIVE 60m
```

VRAMを常時20GB占有することになるので、そのPCで他にGPUを使う作業をするなら
既定（5分）のままのほうが扱いやすいです。

### RTX 5090（32GB）で組む場合

VRAM 32GB あるので、このシステムの用途では**選択肢が一段上がります**。おすすめの順に。

| 優先 | モデル | 量子化 | VRAM目安 | 向いている点 |
|---|---|---|---|---|
| **1** | Qwen3 30B-A3B（MoE） | Q5_K_M | 約20GB | **速い**。実際に計算するのは3B相当なので応答が軽い。抽出・要約中心の本用途と相性が良い |
| 2 | Qwen3 32B（密） | Q5_K_M | 約23GB | 指示の守り方が固い。出典番号の正確さを優先するならこちら |
| 3 | Qwen2.5 32B Instruct | Q5_K_M | 約23GB | 実績重視。日本語の安定感がある |

いずれも 32GB に収まり、コンテキスト16〜32kぶんの余裕も残ります。
**まず 1 と 2 を入れて、同じ質問で読み比べて選ぶ**のが確実です。
1問あたり10〜20秒で返るので、比較は短時間で終わります。

```bash
ollama pull qwen3:30b-a3b
ollama pull qwen3:32b
ollama list                 # ここに出た名前を設定画面の「モデル」に入れる
```

**70B級は勧めません。** 32GBに載せるにはQ3まで落とす必要があり、量子化で劣化した
70Bは、素直な32Bに勝てないことが多いためです。

Blackwell世代（5090）は比較的新しいので、**Ollama は最新版を入れてください。**
古い版はGPUを認識できず、CPUで動いてしまうことがあります。接続テストで
「長い文章の読み取り」に何十秒もかかる場合は、これを疑ってください。

なお索引作成側（PDFの読み取り・OCR）はGPUを使わないので、5090の恩恵は
**AIの回答部分だけ**です。検索の速さは変わりません。

### クラウドと迷ったら

料金だけが理由ならクラウドのほうが安く済みます。この構成だと1問あたり
**0.2〜0.3円**程度（`gpt-4o-mini`、入力8千トークン）で、月1000問でも数百円です。
GPUを買う費用には届きません。

**ローカルにする理由は「マニュアルの中身を社外に出さない」の一点**だと考えてください。
そこが要件なら十分に価値があります。

## 設定

| 環境変数 | 既定 | 用途 |
|---|---|---|
| `MANUAL_ROOT` | `manuals` | PDFの置き場 |
| `MANUAL_DB` | `index.db` | 索引DBの場所 |
| `MANUAL_LIBRARY` | `library.csv` | 台帳のファイル名 |
| `MANUAL_OCR_LANG` | `jpn+eng` | Tesseractの言語 |
| `MANUAL_OCR_DPI` | `300` | OCR時の解像度 |
| `MANUAL_OCR_THRESHOLD` | `16` | この文字数未満のページをOCR対象とみなす |

## 社内で共有する

既定では自分のPCからしか繋がりません（`127.0.0.1`）。同じLANの人に使ってもらうときは
ホストを開きます。

```bash
HOST=0.0.0.0 ./start.sh
```

**認証は付いていません。** 社内LANの外に出す場合は、リバースプロキシ側でBasic認証や
IP制限をかけてください。PDFの配信はPDF置き場の中に限定してあり、索引に外部のパスが
入っていても配信しません。

索引を作り直す必要はなく、PDFを足したら `index` を流すだけです。夜間に流したいときは
cronやタスクスケジューラで次を実行してください。

```bash
.venv/bin/python -m manualsearch index manuals
```

## 規模の目安

| 項目 | 目安 |
|---|---|
| 索引DBの大きさ | 本文の1.5〜2倍程度（1万ページで数百MB） |
| 検索の速さ | 数万ページでも数十ms |
| 取り込みの速さ | テキストPDFは1冊数秒。OCRは1ページ1〜3秒（CPUの数だけ並列に処理します） |

数万冊を超えて全文検索の精度や表記ゆれに不満が出てきたら、この索引をそのまま
Meilisearch などに載せ替える余地があります。まずはこの構成で足ります。
